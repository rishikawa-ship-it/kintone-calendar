# 要件定義書: 設定画面のタブ化とカテゴリ色分け

**文書番号**: REQ_config-tabs
**作成日**: 2026-07-31
**ステータス**: 設計完了
**対象ファイル**: `plugin/src/html/config.html` / `plugin/src/js/config.js` / `plugin/src/css/config.css`
（`desktop.js` は変更しない。設定画面のみで完結。**保存形式（config version 13）も変更しない**）

---

## 1. 背景・目的

設定画面は 7 セクションの縦積みで、機能的に異なる項目の関連が分かりにくい。特に最下部の
「設定の書き出し・取り込み」は存在に気づきにくい。石川さんの要望は「タブや背景の色分けで
分かりやすくしたい」。提示した3案のうち **案A（タブ + カテゴリ色）** を採用する。

**Ctrl+F 併用について**: 石川さんは設定項目を探すときブラウザ検索を「ときどき使う」。
タブ化すると非表示パネルは検索対象外になるため、**全パネルを一時展開する「すべて表示」
トグルを必須要件とする**（FR-4）。

---

## 2. 要件

### 2.1 タブ構成（FR-1）

既存セクションの**DOM 順序を変えずに**、隣接するセクションをパネルで包んでタブ化する
（順序変更は差分を不必要に大きくし、config.js の DOM 参照を壊すリスクを上げるため）。

| # | タブラベル | data-tab | 含まれる既存セクション | アクセント色 |
|---|---|---|---|---|
| 1 | 基本設定 | `basic` | 基本設定（フィールドマッピング） | `#1976d2` 青 |
| 2 | 表示・絞り込み | `display` | 表示・絞り込み（検索対象／フィルタ） | `#2e7d32` 緑 |
| 3 | 権限・色分け | `permission` | 権限・色分け | `#e65100` 橙 |
| 4 | 重複チェック | `overlap` | 重複チェック設定 | `#6a1b9a` 紫 |
| 5 | ビュー個別設定 | `view` | ビュー個別設定 | `#00838f` シアン |
| 6 | ワークフロー | `workflow` | ワークフロー（現在は凍結中） | `#ad1457` ローズ |
| 7 | 書き出し・取り込み | `io` | 設定の書き出し・取り込み | `#546e7a` グレー青 |

- 当初案は 5 タブ（ビュー個別設定を「表示・絞り込み」に同居）だったが、DOM 順序を保つと
  セクションの物理移動が必要になるため独立タブとする。ビュー個別設定は kintone ビューの
  作成・更新を伴い性質が異なるため、独立タブのほうが実態に合う。
- ワークフローと書き出し・取り込みも当初は「その他」1タブに同居させたが、**ワークフローは
  運用を開始すると単体で相当の高さになる見込み**（石川さん指摘）のため別タブに分離した。
- 既定の選択タブは `basic`。

### 2.2 色分けの方針（FR-2）

- **広い面積のベタ塗りはしない**。入力欄が密集する画面で背景に色を敷くとコントラストと
  可読性が落ちるため。
- 色は次の3箇所にだけ使う:
  1. タブの選択時の下線・文字色
  2. セクション見出し（`.kc-config-section-title`）の左ボーダー（4px）
  3. セクション見出し行のごく淡い背景ティント
- サブセクション（`.kc-config-subsection-title`）以下の既存スタイルは変更しない。

### 2.3 タブ切り替え（FR-3）

- `role="tablist"` / `role="tab"` / `role="tabpanel"` と `aria-selected` / `aria-controls` を付与。
- 非選択パネルは**DOM から外さず** CSS で非表示にする（`hidden` 属性 + `display:none`）。
  **収集系（`collectXxx()`）・反映系（`applyXxx()`）・書き出し／取り込みは全パネルの DOM を
  参照するため、DOM から外すと保存内容が壊れる。**
- キーボード操作: `←`/`→` で隣のタブへ移動できる。
- 選択中タブは `sessionStorage`（キーにアプリ ID を含める）に保存し、再読込時に復元する。
  復元値が不正なら `basic` にフォールバックする。

### 2.4 「すべて表示」トグル（FR-4）

- タブバー右端にチェックボックス「すべて表示（Ctrl+F 用）」を置く。
- ON で全パネルを縦積み表示する（従来の見た目に戻る）。各パネルはセクション見出しを持つため
  どのカテゴリか判別できる。
- ON のときタブクリックは**切り替えではなく該当パネルへのスクロール**として振る舞う。
- この状態も `sessionStorage` に保存する。

### 2.5 バリデーションエラーとタブの対応（FR-5）

**最悪のパターンは「非表示タブでエラーになり、原因が画面上に見えない」こと。** 次で防ぐ。

- `validateConfig()` の戻り値に `tabIds`（エラーの発生タブ ID 配列）を**追加**する。
  既存の `valid` / `errors` は変更しないため既存呼び出し元は無改修（追加のみ）。
  - V1（必須フィールド未設定）・V2（開始＝終了） → `basic`
  - V3（初期ビューの値が不正） → `view`
- `collectAndValidateCurrentConfig()` も `tabIds` を返す。
  - `validateAllWorkflows()` のエラー → `other`
- 新規ビュー名の未入力・重複エラー（`saveConfig` 内） → `view`
- 保存失敗時の動作:
  1. `tabIds` の**先頭のタブへ自動で切り替える**（「すべて表示」ON のときは切り替えず該当パネルへスクロール）
  2. `tabIds` の全タブに**エラーバッジ**（●）を付ける
  3. エラーメッセージは従来どおり `#kc-config-error` に表示する
- バッジは `clearError()` で消す。

### 2.6 レイアウト（FR-6）

- 操作ボタン（キャンセル／保存／保存して更新）とエラー表示領域は**タブの外**に置き、
  どのタブでも常に見えるようにする（現状の上部・下部の2箇所とも維持）。
- タブバーはコンテナ幅に収まらない場合は折り返す（`flex-wrap`）。
- 狭幅（`@media (max-width: 600px)`）でも横スクロールを発生させない。

## 3. 受入基準

- **AC-1**: 7 タブが表示され、クリックで対応パネルだけが表示される
- **AC-2**: タブを切り替えても入力値が保持される（切り替え → 戻る → 値が残っている）
- **AC-3**: すべてのタブの入力を含めて**1回の「保存」で全項目が保存される**（タブ化前と同一）
- **AC-4**: 「すべて表示」ON で全パネルが縦積み表示され、Ctrl+F で全項目を検索できる
- **AC-5**: 「すべて表示」ON でタブをクリックすると該当パネルへスクロールする
- **AC-6**: 必須フィールド未設定で保存すると「基本設定」タブへ自動遷移し、バッジが付く
- **AC-7**: 初期ビュー不正・新規ビュー名エラーで「ビュー個別設定」タブへ遷移する
- **AC-8**: ワークフローのバリデーションエラーで「ワークフロー」タブへ遷移する
- **AC-9**: 選択中タブ・「すべて表示」状態が再読込後も復元される
- **AC-10**: 設定の書き出しが全タブの内容を含む（非表示タブの値が欠落しない）
- **AC-11**: 設定の取り込みが非表示タブのセクションにも反映される
- **AC-12**: 600px 幅で横スクロールが発生しない
- **AC-13**: 保存形式（config version 13）が変わらない

## 4. 検証項目

| No | シナリオ |
|---|---|
| T-1 | 各タブをクリックし、表示されるパネルが1つだけであることを確認 |
| T-2 | 全タブに値を入れて保存 → 再読込して全項目が復元されることを確認（AC-3） |
| T-3 | 「すべて表示」ON/OFF の切り替え、ON 時のタブクリックでスクロールすること |
| T-4 | タイトルフィールドを未設定にして保存 → 基本設定タブへ遷移＋バッジ |
| T-5 | ワークフローに不正設定を作って保存 → ワークフロータブへ遷移＋バッジ |
| T-6 | 非表示タブがある状態で書き出し → JSON に全キーが含まれる |
| T-7 | 部分ファイル（例 `filterConfig` のみ）を取り込み → 非表示の表示タブに反映される |
| T-8 | 1280 / 1100 / 600px でタブバーの折返し・横スクロール無しを確認（自動計測可） |
| T-9 | `←`/`→` キーでタブ移動 |

## 5. 前提・非機能

- `desktop.js` は変更しない。カレンダー本体の挙動に影響しない。
- config の保存形式は version 13 のまま（本要件は UI のみ）。
- `config.js` はセクションのラッパー要素（`<section class="kc-config-section">`）を一切参照して
  いないことを確認済み（ID 参照のみ）。したがってパネルで包む改修の影響範囲は小さい。
- 実機検証は `plugin.zip` の手動アップロード＋ハードリロードが必要。
