# 要件定義書: プラグイン設定のエクスポート／インポート

**文書番号**: REQ_config-export-import
**作成日**: 2026-07-28
**作成者**: 管理者（オーケストレーター）
**ステータス**: 設計完了（実装委譲可）
**対象ファイル**: `plugin/src/html/config.html` / `plugin/src/js/config.js` / `plugin/src/css/config.css`
（`desktop.js` は変更しない。設定画面のみで完結する機能）

---

## 1. 背景・目的

1. **環境間コピー**: 開発アプリで作り込んだ設定を本番アプリへ持っていく（現状は画面を見比べて手作業）。
2. **バックアップ／復元**: 設定は肥大化しており（v13: fieldMapping / permissionRules / fieldValueRules / searchTargets / defaultPermission / filterConfig / views / workflows）、誤操作からの復旧手段がない。
3. **設定作成の外部委譲**: ユーザーから「将来的にプラグイン設定の作成を Claude に依頼するかもしれない」との要望あり。**人間または AI がテキストとして設定を書き、それを取り込める**ことを設計要件とする。

→ 3 を満たすため、(a) 書き出し形式を本書に明記し、(b) **一部のキーだけを含む部分的なファイルも取り込める**ことを必須とする。

---

## 2. 要件

### 2.1 エクスポート（FR-1）

- 設定画面の操作で、現在の設定内容を **JSON ファイルとしてダウンロード**する。
- 出力するのは**画面上の現在の入力値**（`collectXxx()` 群で収集した内容）とする。保存済み設定ではなく編集中の内容を書き出す（保存前でも持ち出せる）。
  - 収集時に既存のバリデーションでエラーになる場合は、エクスポートを中止しエラーを表示する（不正な設定を配布しない）。
- ファイル名: `kc-calendar-config_app{アプリID}_{YYYYMMDD-HHmm}.json`
- ダウンロードは `Blob` + `URL.createObjectURL` + 一時 `<a download>` で行う（外部送信は一切しない。§5 参照）。

### 2.2 エクスポート形式（FR-2・人／AI が編集できる形式）

```jsonc
{
  "kcConfigExport": 1,              // このファイル形式のバージョン（固定 1）
  "exportedAt": "2026-07-28T09:30:00.000Z",
  "sourceApp": { "id": "704", "name": "モバイルWi-Fi貸出管理アプリ" },
  "config": {
    "version": 13,                  // プラグイン設定のバージョン
    "fieldMapping": { /* ... */ },
    "searchTargets": [ /* ... */ ],
    "permissionRules": [ /* ... */ ],
    "fieldValueRules": [ /* ... */ ],
    "defaultPermission": { /* ... */ },
    "filterConfig": { /* ... */ },
    "workflows": [ /* ... */ ],
    "views": { /* viewId: { calendarTitle, defaultView } */ }
  }
}
```

- `sourceApp.name` は表示用の参考情報（取り込み判定には使わない）。
- **取り込み側は次のいずれも受け付ける**（寛容なパース。AI・人手で書いたファイルを通しやすくするため）:
  1. 上記のラッパー形式
  2. `config` の中身だけを書いた素の設定オブジェクト（`version` を含む／含まないどちらも可）
  3. 上記のうち**一部のキーだけを含むもの**（例: `workflows` のみ、`filterConfig` のみ）

### 2.3 インポート（FR-3）

- ファイル選択（`<input type="file" accept="application/json">`）で読み込む。読み込みは `FileReader` によるローカル処理のみ。
- パース後、**取り込み確認モーダル**を表示する（既存 `.kc-modal-overlay` パターンを流用）。モーダルの内容:
  1. ファイルの概要（`sourceApp`・`exportedAt`・`version`。無い場合は「不明」と表示）
  2. **ファイルに含まれるキーの一覧をチェックボックスで表示**し、取り込む対象を選べる（既定は全チェック）。ファイルに存在しないキーは行自体を出さない。
  3. §2.4 の検証結果（警告一覧）
  4. 「取り込む」「キャンセル」ボタン。取り込むは破壊的操作のため、ボタン直上に「チェックした項目は現在の設定を上書きします」と明記する
- 「取り込む」を押した時の動作:
  - チェックされたキーのみを `currentConfig` に反映する（**メモリ上のみ**）。既存の `applyXxx()` 群を呼んで画面を再描画する。
  - **`setConfig` は行わない**。ユーザーが画面下部の「保存」／「保存して更新」を押して初めて永続化される（既存のモーダル適用フローと同じ思想）。
  - 反映後、画面上部に「設定を取り込みました。内容を確認して『保存』してください」と案内を表示する。
- インポート後もキャンセル（画面離脱）で元に戻せる（未保存のため）。

### 2.4 検証と警告（FR-4）

取り込み前に検証し、**致命的なものはブロック／環境差はブロックせず警告**とする。

**ブロックする（取り込み不可）**
- JSON としてパースできない
- オブジェクトでない／取り込めるキーが1つも無い
- `version` が現在サポートするバージョン（13）より**大きい**（未来の形式は解釈できない）
- チェックしたキーの値の型が期待と異なる（例: `workflows` が配列でない、`filterConfig` がオブジェクトでない）

**警告のみ（取り込みは可能）**
- `version` が現在より小さい → 「マイグレーションを適用して取り込みます」と表示し、既存の `loadInitialConfig()` のマイグレーション連鎖と**同じ変換を通してから**反映する（v12 以前のファイルも取り込める）
- `sourceApp.id` が現在のアプリ ID と異なる → 「別アプリの設定です。フィールドコード・ビューID・対象アプリIDの読み替えが必要な場合があります」
- 参照されているフィールドコードが**現在のアプリに存在しない** → 該当キーと欠落コードを列挙（例: `fieldMapping.fieldColor: "KC_color" が見つかりません`）。既存 UI は未検出オプションを `kc-option-missing` で表示する仕組みがあるため、取り込み自体は許容する
  - 検査対象: `fieldMapping` の各値、`searchTargets[].fieldCode`、`permissionRules[].fieldCode`、`fieldValueRules[].fieldCode`、`filterConfig.groups[].fieldCode`、`workflows[]` の条件ノード `fieldCode`・`setActions[].targetFieldCode`・`selfFieldCode`・`watchFieldCode`
- `views` のビューIDが現在のアプリに存在しない → 「このアプリに無いビューの設定が含まれます」（views をチェックから外せば回避できる旨も表示）
- `workflows[].actions[].targetAppId` は他アプリ参照のため検証しない（存在確認は行わず、注意文のみ表示）

### 2.5 UI 配置（FR-5）

- 設定画面の**最終セクション**として「設定の書き出し・取り込み」を新設する（既存 6 セクションの後）。
- セクション内容: 「設定を書き出す」ボタン、「設定ファイルを選択」（ファイル入力）、説明文。
- 説明文に明記する内容:
  - 書き出しは画面の現在の内容を JSON にする
  - 取り込みは画面に反映するだけで、保存は別途必要
  - 別アプリの設定を取り込む場合はフィールドコード等の読み替えが必要な場合がある

## 3. 受入基準

- **AC-1**: 「設定を書き出す」で §2.2 形式の JSON がダウンロードされ、`config` に画面の現在値が全キー含まれる
- **AC-2**: バリデーションエラーがある状態でエクスポートすると中止され、エラーが表示される
- **AC-3**: 書き出したファイルを同じアプリで取り込むと、全項目が元の状態に復元される（往復の可逆性）
- **AC-4**: `workflows` のみを含む部分的なファイルを取り込むと、`workflows` だけが置き換わり他のセクションは変化しない
- **AC-5**: 取り込み確認モーダルで一部のキーのチェックを外すと、そのキーは反映されない
- **AC-6**: 取り込み直後は未保存であり、「保存」を押すまで `setConfig` されない（キャンセルで破棄できる）
- **AC-7**: 不正な JSON・空オブジェクト・`version` が 13 超のファイルは取り込みがブロックされ、理由が表示される
- **AC-8**: v12 以前の設定ファイルはマイグレーションを通して取り込まれる
- **AC-9**: 別アプリの設定・存在しないフィールドコードを含むファイルは、警告付きで取り込める（ブロックされない）
- **AC-10**: ラッパー形式・素の設定オブジェクト・部分オブジェクトのいずれも取り込める

## 4. 検証項目

| No | シナリオ |
|---|---|
| T-1 | 書き出し → ファイル名・JSON 構造の確認 |
| T-2 | 同一アプリで往復（書き出し→取り込み→保存→再読込）して全項目一致 |
| T-3 | `workflows` のみのファイルを取り込み、他セクションが不変であることを確認 |
| T-4 | チェックを外したキーが反映されないことを確認 |
| T-5 | 取り込み後に保存せずキャンセル → 設定が変わっていないことを確認 |
| T-6 | 壊れた JSON・空 `{}`・`version: 99` でブロックされることを確認 |
| T-7 | 別アプリ（891→704 等）の設定を取り込み、警告が出て取り込めることを確認 |
| T-8 | 存在しないフィールドコードを含むファイルで警告表示と `kc-option-missing` 表示を確認 |
| T-9 | views を含むファイルで、チェックを外して回避できることを確認 |

## 5. 前提・非機能

- **外部送信を一切行わない**: 書き出しは Blob によるローカルダウンロード、読み込みは FileReader によるローカル読み取りのみ。設定内容を外部エンドポイントへ送る処理は実装しない。
- 設定にはフィールドコード・ユーザーコード（権限ユーザー設定）・アプリ ID が含まれる。ファイルの取り扱い（共有先）は運用者の責任範囲であり、その旨を説明文に含める。
- config のバージョンは 13 のまま（本機能は保存形式を変更しない）。
- 実装は設定画面のみ（`config.js` / `config.html` / `config.css`）。`desktop.js` は変更しない。
- 実機検証は `plugin.zip` の手動アップロードが必要（`MEMORY.md` の運用ルール）。
